# Rune Phase 4 — Consumer Groups & Compaction Plan

**Goal:** Kafka-style consumer groups (group membership + generation/epoch, partition assignment/rebalance, durable offset commit/fetch) and log compaction (key-based retention keeping the latest value per key, tombstones, a cleaner). Ties Phase 1 (`libs/storage` Log + keyed record batches) + Phase 3 (`libs/replication` partitions) + a single-writer coordinator.

**Reference:** Kafka is the bible for the data-plane semantics here (as Aeron Cluster was for Phase-2 consensus). Mirror Kafka's `GroupCoordinator` (JoinGroup/SyncGroup, generationId, session timeout, assignors) and `LogCleaner`/`OffsetMap` (dedup map, compaction, tombstone delete-retention) EXACTLY. Spec: `docs/specs/2026-09-10-rune-broker-design.md`. **Engineering law:** `CLAUDE.md` §4 — single-writer `doWork(nowNs)` agents, NO busy-spin (injected advanceable clock, bounded drivers with hard cap + ASSERT), Aeron ring buffers/IdleStrategy, flat SBE codecs, no hot-path alloc, `-j2`.

**New lib:** `libs/coordination` (`rune_coordination`, namespace `rune::coordination`) for group coordination + offsets; compaction lives in `libs/storage` (extends the Phase-1 Log). Unit + integration + benchmark targets mirror the existing libs.

## Global constraints
C++23; single-writer coordinator (no locks on the hot path); injected clock in tests (bounded, no spin); reuse Phase-1 `Log`/`RecordBatch` (keys) + Phase-3 partition model; NEVER conan create/export/upload; build `-j2`. Dozens of unit tests + integration + benchmarks per unit; disaster/recovery scenarios (coordinator failover, member crash mid-rebalance, compaction crash recovery). Board + live feed updated per unit. Unique temp paths (getpid()+atomic counter).

## Units (each = a Planka card P4-*; TDD; review→fix→Done; board + live updated)

- **P4-1 — Consumer offset store (pure, durable).** `OffsetStore`: durable per-`(group, topic, partition)` committed offset + metadata; `commit(group,tp,offset,metadata)`, `fetch(group,tp)`, `fetchAll(group)`; monotonic per key (a lower commit is allowed only explicitly — mirror Kafka's OffsetCommit which overwrites); file/mmap-backed with crash recovery (replay on reopen → identical state, like NodeStateFile/Log). SBE OffsetCommit/OffsetFetch request/response codecs. TDD: commit→fetch round-trip, overwrite, multi-group isolation, durability across reopen, torn-tail recovery.
- **P4-2 — Group membership + generation (pure, single-writer).** `GroupCoordinator` core state machine (Kafka group states: Empty→PreparingRebalance→CompletingRebalance→Stable, + Dead): members `join(memberId?, sessionTimeout)`/`leave`/`heartbeat(nowNs)`; generationId bumps on every membership change; member session expiry via injected clock (`doWork(nowNs)` reaps timed-out members → triggers rebalance); a member's `assignment`. NO spin. TDD: join creates/grows group + bumps generation, heartbeat keeps alive, session timeout evicts + rebalances, leave shrinks, generation monotonic, leader-member selection.
- **P4-3 — Partition assignment / rebalance (JoinGroup/SyncGroup).** Faithful Kafka rebalance: on membership change the coordinator gathers member subscriptions (JoinGroup), the group leader computes an assignment, SyncGroup distributes per-member assignments; generation-fenced (stale-generation requests rejected). Assignors: `RangeAssignor` + `RoundRobinAssignor` (+ optional sticky). TDD: N members / M partitions → balanced assignment, rebalance on join/leave reassigns, stale-generation fenced, every partition assigned exactly once, assignor correctness (range vs round-robin exact distributions).
- **P4-4 — Log compaction (cleaner + offset map).** Mirror Kafka `LogCleaner`: a `OffsetMap` (dedup map key→latest offset) built over a log's dirty segments; compact a log keeping only the latest record per key (drop superseded), remove tombstones (null-value) after `deleteRetentionMs`, preserve offsets (compacted log keeps original offsets, gaps allowed), never compact past the active segment / high-watermark. Ties Phase-1 `Log` + keyed `RecordBatch`. TDD: latest-value-per-key kept, superseded dropped, tombstone removes key then itself after retention, offsets preserved w/ gaps, HW/active-segment boundary respected, compaction is idempotent, crash mid-compaction recovers (swap-file/atomic rename like Kafka).
- **P4-5 — Integration: consumer-group + compaction end-to-end + disaster/recovery.** Deterministic, bounded, real components: a group of consumers joins → gets balanced assignment → commits offsets → a member crashes mid-session → rebalance reassigns its partitions → new member resumes from committed offset (no double-consume/no-loss of commit); coordinator failover (offset store durable → new coordinator recovers committed offsets + group state); compacted topic read correctness (consumer reading a compacted partition sees only latest-per-key); compaction during active produce (HW boundary safe). Every disaster scenario. Invariants: each partition assigned once, generation monotonic, committed offsets never lost across failover, compaction never drops the latest value or crosses HW.
- **P4-6 — Benchmarks.** OffsetCommit/OffsetFetch latency (p50/p99), rebalance time vs group size, compaction throughput (MB/s, records/s) + OffsetMap build cost, assignor cost vs partitions×members. Latency-focused, no hot-path alloc, short min_time.

## Execution & exit
Per unit: card→In Progress + plan note → implementer (TDD, faithful Kafka, bounded/no-spin) → quality review → fix loop → commit → card→Done → push test/benchmark live. Exit: consumer groups with durable offsets + balanced generation-fenced rebalance surviving member crash + coordinator failover, and key-based log compaction that preserves the latest value per key + tombstone semantics without crossing the high-watermark — all green (bounded, no spin, -j4 stable), benchmarked.
