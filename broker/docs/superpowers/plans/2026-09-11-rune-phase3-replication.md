# Rune Phase 3 — Replication & Self-Healing (data plane) Plan

**Goal:** Kafka-style partition replication with majority-in-memory durability + high-watermark, ISR management, leader-epoch fencing, leader failover from ISR, follower catch-up, and Aeron Archive integration for durable recording/replay. Ties Phase 1 (`libs/storage` Log) + Phase 2 (`libs/consensus` metadata quorum) + Aeron.

**Spec:** `docs/specs/2026-09-10-rune-broker-design.md` §4 (data-plane hot path), §5 (control plane — done P2), §8 (leader-epoch fencing), §6.5/6.6 (Archive, leader-epoch/producer-state). **Bible:** `CLAUDE.md` §4 (faithful Aeron, single-writer, no busy-spin, aeron ring buffers/IdleStrategy, `-j2`).

**Model:** The control plane (Phase-2 consensus) owns metadata: per partition `{leader, replicas, ISR, leaderEpoch}`. The data plane (this phase) replicates each partition leader→followers over Aeron; a write is durable when a MAJORITY of the ISR hold it in memory; the leader advances the **high-watermark**; consumers read ≤ high-watermark. Aeron Archive records committed segments async (durable disk) + enables follower catch-up replay. This is Kafka's ISR model (NOT Aeron Cluster's single-log Raft — that was the metadata plane).

**New lib:** `libs/replication` (`rune_replication`, namespace `rune::replication`), mirroring `libs/storage`/`libs/consensus` conventions; unit target `rune_replication_tests` + integration `rune_replication_integration_tests`.

## Global constraints
C++23; single-writer per partition (one leader thread owns the partition Log — no locks on the hot path); Aeron transport (ExclusivePublication/tryClaim) + aeron IdleStrategy; NO busy-spin (injected clock in tests, bounded drivers); reuse Phase-1 `Log`/`LeaderEpochCache` + Phase-2 metadata; NEVER conan create/export/upload; build `-j2`. Dozens of unit tests + integration + benchmarks per unit; cluster disaster/recovery scenarios.

## Units (each = a Planka card P3-*; TDD; board + live updated)

- **P3-1 — Replication protocol messages + high-watermark logic (pure).** SBE messages for data-plane replication (FetchRequest/FetchResponse or leader-push AppendRecords + AppendReply carrying leaderEpoch, partition, fetchOffset, batches, high-watermark). A pure `ReplicaSet` computing the high-watermark = the highest offset replicated to a MAJORITY of the ISR (min over the majority; mirror Kafka's HW = min(ISR fetch offsets) when ISR=all, majority variant per our spec). Leader tracks per-follower `logEndOffset`/`fetchOffset`. TDD: HW advances only on majority; never regresses; a lagging follower doesn't hold back HW once out of ISR.
- **P3-2 — ISR management + leader-epoch fencing (pure).** `IsrManager`: shrink ISR when a follower's fetch lags beyond `replicaLagMaxMs`/offset; grow (rejoin) when caught up to HW; min-ISR policy (reject produce if ISR < minIsr when acks=all). Leader-epoch: every replication request/append carries `leaderEpoch`; a replica rejects a request with a stale epoch and a leader steps down on a higher epoch (fencing, spec §8). Uses Phase-1 `LeaderEpochCache` for truncation-on-epoch-change. TDD: ISR shrink/grow at thresholds, epoch fencing, min-ISR gate.
- **P3-3 — PartitionReplica (leader/follower roles, single-writer).** Ties `Log`(P1) + replication + ISR + leader-epoch per partition. Leader: `append(batch)` → assign offsets → replicate to followers → advance HW on majority ack → expose committed reads (≤HW). Follower: apply replicated records to its Log; on epoch change, truncate via LeaderEpochCache; send fetch/ack. A `doWork(nowNs)` single-writer step (no locks). TDD with fake transport + injected clock (bounded, no spin): produce→replicate→HW→consume-committed; follower catch-up; epoch-change truncation.
- **P3-4 — Aeron Archive integration (recorder/replay) [risk-gated].** `PartitionRecorder` records a partition Log to Aeron Archive (startRecording/getRecordingPosition); `PartitionReplay` replays from Archive for follower catch-up + cold recovery. Feasibility spike first (does aeron-archive run embedded here like the media driver did in P2-8?); if not, document + defer the live-Archive wiring, keeping the in-memory/file recording as the Phase-3 deliverable. Also finish the deferred Phase-2 Election catchup (Archive-backed) if Archive is feasible.
- **P3-5 — Leader failover & self-healing.** On leader death (consensus/liveness signal), the control plane (Phase-2 metadata quorum) elects a new partition leader from the ISR (guaranteed to hold all committed data), bumps leaderEpoch, fences the old leader. Under-replication repair: assign a healthy node as a new follower; it bootstraps (snapshot + tail replay) and re-enters ISR. Ties consensus metadata → replication. Integration-flavored.
- **P3-6 — Multi-node replication cluster + disaster/recovery integration tests.** 3/5-node replicated partitions over the in-memory (and, if feasible, real-Aeron) transport, deterministic + bounded: produce → majority-replicate → HW; **kill leader → failover elects an ISR member, NO committed-message loss, per-partition order intact, HW preserved**; minority partition can't advance HW (safety); follower catch-up + rejoin ISR; node restart recovers + re-syncs; leader-epoch fencing prevents split-brain double-write. Assert: no committed loss, order, replica log convergence, HW monotonic. Every disaster scenario.
- **P3-7 — Replication benchmarks.** produce→majority-ack latency (the p99<100µs target path!), HW advance, fetch/append throughput, Archive record. Latency-focused, no hot-path alloc.

## Execution & exit
Per unit: card→In Progress + plan note → implementer (TDD, faithful, bounded/no-spin) → quality review → fix loop → commit → card→Done → push test/benchmark. Exit: replicated partitions on a 3/5-node cluster with majority-durable produce + HW, leader failover with zero committed loss, ISR + epoch fencing safe under partition, follower catch-up + restart recovery — all green (bounded, no spin), benchmarked, with the p99 produce-ack latency measured toward the <100µs goal.
