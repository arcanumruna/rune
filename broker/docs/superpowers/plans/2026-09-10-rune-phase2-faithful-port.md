## Global constraints (from CLAUDE.md §4 + blueprint §6)
C++23; single-writer `doWork(nowNs)` agents, no locks; Aeron's own ring buffers + `IdleStrategy` (not `common`); reusable SBE codecs as fields, `tryClaim` zero-copy; release/acquire fences (`std::atomic`); pre-allocated scratch (quorum `rankedPositions`); `CLOCK_MONOTONIC_RAW` once per cycle; no hot-path allocation. cmake not on PATH; rune-protocol via include path; `aeron/1.41.4`; NEVER conan create/export/upload. Every unit: dozens of unit tests + integration where possible + benchmarks (per the testing mandate).

## Units (each = a Planka card; TDD; live-updated)

- **P2P-1 — ElectionState enum + ClusterMember.** `ElectionState` (18 states, exact ordinals; ref §1). `ClusterMember` (fields ref §2.1) + the exact static algorithms (ref §2.2/§2.3): `compareLog`, `quorumThreshold=(n>>1)+1`, `quorumPosition(members, rankedPositions&, nowNs, timeoutNs)` (pre-allocated array, insertion-sort top-K), `hasActiveQuorum`, `hasQuorumAtPosition`, `isUnanimousLeader`, `isQuorumLeader`, `willVoteFor`. Pure, deterministic. Dozens of tests incl. quorum-position rankings, compareLog ordering, vote predicates.
- **P2P-2 — NodeStateFile.** mmap-backed `candidateTerm{candidateTermId:int64, timestamp:int64, logPosition:int64}` (ref §5.1). `proposeMaxCandidateTermId(id, logPos, tsMs)` writes only if greater; write order logPosition→timestamp→candidateTermId with a **release store** (`std::atomic<int64_t>` release), read with **acquire**; `msync(MS_SYNC)` when syncLevel>0. Reworks the vanilla `PersistentState`. Tests: monotonic propose, persistence-across-reopen, release/acquire correctness (single-writer), sync durability.
- **P2P-3 — TermLog + TermEntry.** RecordingLog term-metadata (ref §5.2), non-Archive Phase-2 form: append a `TermEntry{recordingId, leadershipTermId, termBaseLogPosition, logPosition, timestamp, serviceId, type, isValid}`; `lastTerm`, `getTermEntry(termId)`, `commitLogPosition(termId, pos)`, `isValid` invalidation. Durable file. Tests: term-entry lifecycle, base-position accumulation, reload.
- **P2P-4 — Consensus SBE message codecs.** Flat little-endian SBE (schema id 111) encode/decode for the 10 messages (ref §3.1): CanvassPosition(50), RequestVote(51), Vote(52), NewLeadershipTerm(53), AppendPosition(54), CommitPosition(55), CatchupPosition(56), StopCatchup(57), TerminationPosition(75), TerminationAck(76). 8-byte SBE header (blockLength/templateId/schemaId/version). Reusable encoder/decoder holding the buffer; `AppendPosition`/`CommitPosition` kept ≤24B (cache-line, ref §3.1 note). Reuses rune-protocol CRC/varint where apt. Dozens of round-trip + field + header + fragment tests.
- **P2P-5 — Election state machine.** `rune::consensus::Election` — 18-state `doWork(nowNs)` switch (ref §1), fields ref §2.1, and handlers `onCanvassPosition/onRequestVote/onVote/onNewLeadershipTerm/onAppendPosition/onCommitPosition`, `placeVote`, `state()` transition (sets the state counter with a release store). Non-Archive states (LEADER_LOG_REPLICATION/REPLAY, FOLLOWER_LOG_REPLICATION/REPLAY/CATCHUP*) implemented as structurally-exact pass-throughs (no Archive; catchup/replay complete immediately over Rune's local log) so the protocol + transitions are faithful. Emits messages via a `ConsensusPublisher` interface (fake in tests). Dozens of tests: canvass→nominate→ballot→leader, follower ballot, up-to-date `compareLog` vote decisions, NLT handling, single-node fast path, timeouts.
- **P2P-6 — ConsensusPublisher + ConsensusAdapter.** Publisher: one `ExclusivePublication` per peer (abstracted; fake in tests), reusable SBE encoders, `tryClaim` for fixed-size + `offer` for var-length. Adapter: `FragmentAssembler` + SBE decoders → dispatch to agent `onXxx` (FRAGMENT_LIMIT=10). Tests over an in-memory publication.
- **P2P-7 — ConsensusAgent (single-writer) + AgentRunner + IdleStrategy.** `doWork(nowNs)` structure (ref §4.2, minus Archive/service bits): sample clock once, poll adapter → dispatch, drive `election.doWork(nowNs)` (or normal leader/follower `updateLeaderPosition`/`updateFollowerPosition` once elected), role counter (FOLLOWER/CANDIDATE/LEADER), pre-allocated `quorumPosition` array. `AgentRunner` (single `std::thread` duty-cycle) + `BackoffIdleStrategy`/`BusySpinIdleStrategy` matching Agrona `idle(workCount)`/`reset()`. **Threaded integration test:** producers feed the agent via an Aeron/Agrona ring buffer (M2O) — no loss / single-writer visibility.
- **P2P-8 — Aeron transport integration (risk-gated).** Real `aeron::ExclusivePublication`/subscription + `FragmentAssembler` + embedded media driver. Feasibility spike first; if the sandbox can't run a media driver, keep the in-memory bus as the proven deliverable and document, deferring live-Aeron wiring.
- **P2P-9 — Multi-node cluster integration tests.** 3/5 in-process ConsensusAgents over an in-memory transport, manual clock: exactly one leader elected via canvass→nominate→ballot; NewLeadershipTerm/AppendPosition/CommitPosition converge; leader failover; minority partition cannot commit; restart recovers candidateTermId + term log. Assert Election Safety, Leader Completeness (via commit rules), State Machine Safety.
- **P2P-10 — Consensus benchmarks.** doWork tick, full election round, per-message SBE encode/decode via tryClaim path, quorumPosition compute — latency-focused, no-alloc asserted where feasible.
