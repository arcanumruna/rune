# Rune Phase 5 — Exactly-Once / Transactions Plan (FINAL PHASE)

**Goal:** Kafka-style exactly-once semantics (EOS): an idempotent producer (dedup by producerId+epoch+sequence), transactional producer (transactionalId, a transaction coordinator, begin/addPartitions/commit/abort, a durable transaction log + control markers), read-committed consumer isolation (LSO + aborted-transaction filtering), and exactly-once across produce→consume→produce (read-process-write with transactional offset commits). Ties Phase 1 (`libs/storage` Log + ProducerState), Phase 3 (`libs/replication` partitions), Phase 4 (`libs/coordination` offsets/groups).

**Reference:** Kafka's EOS design (KIP-98 idempotence + transactions, KIP-129) is the bible for the semantics here. Mirror Kafka's `ProducerStateManager` (sequence/epoch dedup), `TransactionCoordinator`/`TransactionStateManager` (transactionalId→PID, txn state machine, `__transaction_state`), transaction markers (control batches), and read-committed `LSO`/aborted-txn index EXACTLY. **Engineering law:** `CLAUDE.md` §4 — single-writer `doWork(nowNs)`, NO busy-spin (injected clock, bounded drivers), flat SBE codecs, no hot-path alloc, `-j2`.

**New lib:** `libs/transaction` (`rune_transaction`, namespace `rune::transaction`) for the transaction coordinator + markers; the idempotent-producer dedup extends `libs/storage` `ProducerState`; read-committed isolation ties `libs/replication`/`libs/storage` reads. Unit + integration + benchmark targets mirror the existing libs.

## Global constraints
C++23; single-writer coordinator (no locks on the hot path); injected clock in tests (bounded, no spin); reuse Phase-1 `ProducerState`/`Log` + Phase-3 partitions + Phase-4 `OffsetStore`; NEVER conan create/export/upload; build `-j2`. Dozens of unit tests + integration + benchmarks per unit; disaster/recovery (coordinator failover mid-transaction, zombie fencing, crash recovery of in-flight txns). Board + live feed updated per unit. Unique temp paths (getpid()+atomic counter).

## Units (each = a Planka card P5-*; TDD; review→fix→Done; board + live updated)

- **P5-1 — Idempotent producer dedup (producerId + epoch + sequence).** Extend/build a `ProducerStateManager` over `libs/storage` `ProducerState`: each record batch carries `{producerId, producerEpoch, baseSequence}`; the broker tracks per `(producerId, partition)` the last appended sequence + epoch (a small window of the last N batches for retry dedup). Reject an exact DUPLICATE batch (same epoch+sequence → treat as already-applied, return the prior offset, do NOT re-append) and reject an OUT-OF-ORDER sequence gap (`OutOfOrderSequence`). Epoch fencing: a batch with a lower producerEpoch is rejected (`InvalidProducerEpoch`); a higher epoch resets the sequence tracking. Persist producer state (snapshot) for recovery. TDD: first batch accepted, duplicate returns same offset (no double-append), gap rejected, epoch bump fences old, snapshot+recover restores dedup state.
- **P5-2 — InitProducerId + TransactionCoordinator state machine (pure, single-writer).** `TransactionCoordinator`: `initProducerId(transactionalId?) -> {producerId, producerEpoch}` (allocates a PID; for a transactionalId, bumps the epoch to FENCE a previous producer — zombie fencing); a per-transactionalId txn state machine mirroring Kafka `TransactionState`: Empty → Ongoing → PrepareCommit/PrepareAbort → CompleteCommit/CompleteAbort (+ Dead); `addPartitions(txnId, partitions)`, `beginCommit`/`beginAbort`. Transaction timeout via injected-clock `doWork` (abort a stuck Ongoing txn). NO spin. TDD: initProducerId allocates + epoch bump fences, addPartitions accumulates, state transitions valid/invalid rejected, txn timeout aborts, epoch fencing of a zombie.
- **P5-3 — Transaction log + control markers.** A durable transaction-state log (`__transaction_state` equivalent) recording txn metadata transitions (append + crash recovery replay → identical state, mirror OffsetStore/NodeStateFile). `EndTxn(commit|abort)` drives writing COMMIT/ABORT **control batches** (control records) to each partition in the transaction; SBE codecs for the transaction messages (InitProducerId/AddPartitionsToTxn/EndTxn/TxnMarker) + the control-batch format. Compute the marker's effect on a partition's LSO. TDD: txn log durable + recover, EndTxn writes a marker to every involved partition, control-batch encode/decode byte-exact, commit vs abort markers.
- **P5-4 — Read-committed isolation (LSO + aborted-txn index).** Partition read path gains an isolation level: `read_uncommitted` (reads ≤ HW as today) vs `read_committed` (reads only ≤ **LSO** = the offset of the first still-open transaction, and FILTERS OUT records belonging to aborted transactions using an aborted-transaction index built from ABORT markers). Maintain the LSO as transactions begin/commit/abort; maintain the aborted-txn index per partition. TDD: read_committed hides records of an in-flight txn (≤LSO boundary), a committed txn's records become visible after the COMMIT marker, an aborted txn's records are filtered out entirely, read_uncommitted still sees everything ≤ HW, LSO advances correctly as the oldest open txn resolves.
- **P5-5 — Exactly-once end-to-end integration + disaster/recovery.** Deterministic, bounded, real components: a transactional producer does begin→produce to N partitions→(atomically) commit → a read_committed consumer sees ALL-or-NOTHING (no partial-transaction visibility); an aborted txn → the consumer sees none of it; **read-process-write (consume→transform→produce + transactional offset commit) is exactly-once** (no duplicates, no loss on ret/replay). Disaster: a producer retry re-sends a batch → dedup makes it exactly-once; a ZOMBIE producer (fenced by epoch) can't write; **coordinator failover mid-transaction** → the new coordinator recovers txn state from the durable log, resolves in-flight txns (commit/abort), writes missing markers; a partition-leader failover mid-txn preserves atomicity. Every disaster scenario. Invariants: no duplicate delivered, no aborted record visible under read_committed, a committed txn is fully visible atomically, LSO never exposes an open txn, producer epoch fencing prevents zombie double-write.
- **P5-6 — Benchmarks.** Idempotent-dedup overhead per batch (the hot path — should be ~ns), transaction begin/commit latency (p50/p99), marker write cost, read-committed filtering overhead vs read_uncommitted, InitProducerId/epoch-bump cost. Latency-focused, no hot-path alloc, short min_time.
