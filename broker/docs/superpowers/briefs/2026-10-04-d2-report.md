# D2 report — non-worker thread placement + node-driver idle (2026-10-04)

## Status
Implemented, tested, A/B'd. The mechanism is fixed: worker preemption is ~150x lower in thread placement and ~16x
lower in fused. **Thread-placement latency did NOT recover.** The CPU contention moved to core 0, where the three
co-located nodes' control planes now share one core.

## What changed
- `NodeConfig::nonWorkerCpus` (override: `RUNE_NONWORKER_CORES`, a cpu list). When workers are pinned, HostDefaults
  derives it as the allowed CPUs minus the worker cores:
  - Conventional layout (derived, or an explicit base equal to the derived one; the bench harness passes
    `RUNE_WORKER_CORE_BASE=1+i*W`): excludes every co-located node's worker cores.
  - Any other layout: excludes only this node's own cores, because the other nodes' cores are unknown.
  - Empty complement: affinity is left unchanged, with one warning in the startup warning line.
  - An explicit override is filtered to the allowed mask, with a warning.
  - Logged as `nonWorker=` in the effective-config line.
- `ThreadAffinity.h` adds `pinThreadToCpus`, `pinCurrentThreadToCpus`, `currentThreadCpus` and an RAII
  `ScopedThreadAffinity`. These are Linux-only (pthread_setaffinity_np); elsewhere they return ENOTSUP and do nothing.
- `BrokerNode::start` pins its own thread to the set for the whole of start(), then restores the caller's mask. Every
  thread start() creates inherits the set: the threaded node driver, the Aeron client conductor (thread placement), the
  runtime, admin, cleaner, startup pump and portable flushers. Workers re-pin to their own core on their first pass.
  `main()` pins the main thread and the signal thread after start(). This follows the A4 io-wq approach: same allowed-mask
  derivation and the same filtering of explicit lists.
- Node driver idle: an unset `RUNE_AERON_DRIVER_IDLE` now gives Aeron `backoff` in shard mode (10 spins, 20 yields, then
  park 1 us..1 ms; never busy-spin) and `sleep-ns` in legacy mode. The override still wins. Per-worker invoker drivers
  keep their previous string. Logged as `drvIdle=`.
- Thread placement was not dropped or deprecated.

## A/B (k3s-node-01)
Setup: 20k rec/s open loop, 3 nodes, acks=all, 1 KiB, MTU 1408 with GSO, logs off, one run per arm, all errors=0.

| arm | p50 / p99 us | worker involuntary switches /5 s (sum of 3) |
|---|---|---|
| thread, before (1767c3d) | 8,651 / 187,695 | 177k (65.5k / 71.7k / 40.0k) |
| thread, after (68c3a62) | 13,173 / 184,549 | **1.2k** (396 / 437 / 369) |
| fused, before | 598 / 40,370 | 20.8k |
| fused, after | 549 / 50,594 | **1.3k** |

- Proof of path, after: every node logs `nonWorker=0 drvIdle=backoff`. Every non-worker thread shows
  `Cpus_allowed_list=0` and the workers show 1, 2 and 3.
- Each threaded node driver dropped from ~47% to ~20% CPU.
- Raw data is in `/root/d2b/results/` on the box: ab.txt, ab2.txt, per-thread samples and the scripts. The build and
  source dirs were deleted; 14 GB of disk is free.
- The first fused-before attempt aborted with "rune_broker running": the previous arm's kill -9'd brokers were still
  exiting. That arm was rerun alone after a wait-for-exit guard was added (ab2.sh).

## Concerns
1. **Thread latency is not fixed. The diagnosis's causal step ("worker preemption causes the latency") is refuted on
   this box.** With the workers clean, core 0 now carries 3 node drivers (~60%), 3 runtimes (~45%), admin and cleaner,
   plus a share of the unpinned client. That is more than one core. The drivers now take 21-23k involuntary switches
   per 5 s and the runtimes 8-18k (before: 0.6-3k and 2.6-6.7k).
   - Next software lever: find out why a node driver that carries only control-plane traffic still burns ~20% CPU at
     backoff, and the runtime ~15%. An FR waterfall on 68c3a62 in thread placement would localize which hop is on the
     ack path.
2. p50 and p99 come from single runs. Thread p50 went 8.7 to 13.2 ms, fused p99 went 40 to 51 ms. Both are within the
   run-to-run spread seen before (fused p99 was 17-30 ms in §4.12 and 43 ms in the diagnosis). No regression or
   improvement is claimed.
3. io-wq placement was left unchanged. With an explicit core base, A4 still leaves io-wq inheriting the worker's core
   (`ioWq=inherit` in these runs). The new "conventional explicit layout" detection could also feed the io-wq default.
   I didn't apply it, so the A/B would not be confounded.
4. The Linux pin path is proven by the box's `/proc` Cpus_allowed_list readings. The Linux-only ThreadAffinity unit test
   was not run, because the suite runs on the Mac.
5. Planka MCP failed to connect and `rune-live.sh` could not reach live.regressorspath.com, so no tickets or dashboard
   pushes were made.
