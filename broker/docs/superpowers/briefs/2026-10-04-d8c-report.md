## The problem

In shard mode, the gateway paused a slow gateway-routed client only after the worker's Held signal arrived.

- That signal is one ret_ hop behind the worker, so it raced the client's burst.
- With the host-derived transport (64 KiB loopback MTU), one poll can carry hundreds of frames. The gateway forwarded the burst before Held arrived.
- Measured result on Linux: the pause engaged only after 27–32k frames, or not at all. The worker's op drain hit about 28k ack-room pauses, and other sessions stalled behind them.

## Design as built

### Per-session credit budget

- Each gateway session has a **produce credit budget**: `ClientGateway::kDefaultSessionProduceCredits = 1024`.
- Config knob: `RUNE_GATEWAY_PRODUCE_CREDITS`, accepted range 1..4096. A `static_assert` ties the maximum to ≤ 1/4 of `SessionAckSink::kAckCapacity`.
- Why 1024:
  - It is 1/16 of a worker's ack queue (16384), so 16 fully stalled gateway sessions fit beside the per-pass intake reserve.
  - It costs a well-behaved client nothing. By Little's law, 1024 in flight at a 1 ms round trip is 1M batches/s per session.

### Taking a credit (gateway)

- `Session::produceInFlight` goes up by one each time `handleProduce` gets `EnqueueResult::Enqueued` for a produce in shard mode.
- Produces that the gateway answers itself take no credit: redirect, UnknownTopic, NotLeader, back-pressure NotLeader, MessageTooLarge, bootstrap NotLeader and CRC errors.

### Returning a credit (worker → gateway)

- The return happens when the worker's `SessionAckSink` **claims** the ack. It does not happen when the ack is queued, and not while the ack is held.
- New `AckEntry::credit` field. The worker sets it from a new worker-local field, `WorkerReturn::gatewayCredit`. That field is **not encoded**, so the pinned SBE layout is unchanged.
- `gatewayCredit` is set for every op-ring produce answer:
  - `produceCore_` with `fromOp` covers append, refusal, the HW fire / timeout of a parked acks=all, Strict fsync, and purge (parked waiters carry the struct);
  - `refuseNotOwned_`, the ownership-guard refusal.
- Direct worker-ingress acks never return credits.
- On a successful claim, the sink adds one to the session's `Edges::credits`.
- `reportCredits(tryReport(sid, n))` reports each non-zero count:
  - at most one report per session per pass (coalesced);
  - if the return ring is full, the count is kept and retried. It is never lost and never double-counted.
- The report travels as the new `SessionSignalKind::Credit = 6`, with the count in `baseOffset`. It uses the existing `trySessionSignal_` return path.
- No new cross-thread primitive, no atomics, no allocation, no virtual calls.
- Cost on the direct-ingress hot path: one extra branch on `a.credit` per successful claim.

### Pausing

- `admitClientFrame_` is the per-frame decision of the existing controlled poll.
- When nothing is paused it is one branch: `(heldSessions_ | creditBlockedSessions_) == 0`.
- Otherwise `produceFramePause_` returns Held or NoCredit, and the frame is ABORTed. `heldProduceAborts_` counts every pause; `creditProduceAborts_` counts the credit ones.
- Because a credit is taken synchronously at forward time, the frame after the budget is ABORTed **in the same poll**. The worker never holds more than the budget of one session's routed acks, whatever the burst size, MTU or socket buffers.

### Session close and edge cases

- Close (Disconnect, reap, SessionFailed — all go through `closeSession_`) drops the budget and the blocked count. A late Credit for that session finds no session and is ignored.
- A Credit larger than what is in flight should be impossible. It is clamped to zero, counted in `produceCreditUnderflows_` and logged (rate-limited). It is never treated as a negative budget.

### Lease

- A credit-paused session has its image stopped by the gateway, so its Keepalives queue behind the aborted frame. It is therefore leased like a held session (`maxHeldIdleNs_`).
- Leaving the credit pause refreshes `lastSeenNs`, in the same way a Released edge does.
- A dead client still shows up as Lost (NOT_CONNECTED) and is reaped on the normal lease.

### acks=0 and acks=all

- acks=0 means "Leader": the worker always sends an ack. So acks=0 and acks=all each hold exactly one credit, from forward until claim.
- A parked acks=all produce keeps its credit until the HW fires and the ack is claimed.

### Unchanged

- D8b's Held/Released and Lost/Found/Progress semantics are untouched.
- When a session is Held, the gateway still pauses it, even if it has credits left. Credits that come back while Held are reused only after Released.

### Other changes

- The test seam `controlledPollFramesForTest` runs the real `admitClientFrame_` plus `onClientFrame_`. `onFragment`'s body was split out into `onClientFrame_` so the seam can call it.
- `ShardModeRegression.SlowEndpointUnawareClientCannotStarveTheShard` now uses the host-derived transport. The legacy-transport workaround and its KNOWN ISSUE comment are removed.

## Concerns / follow-ups

- **No independent review.** The brief said not to spawn subagents, so the usual Opus review of my own change was not run. Recommend one before merge.
- **Signal volume:** a gateway-path session that is reading emits up to one Credit signal per worker pass. This is bounded by the ack count, and the per-ack post-ack notification already exists.
  - If the gateway path ever becomes hot, the post-ack liveness notification could be folded into Credit for routed produces. Credit already refreshes the lease when it ends a pause.
  - Credit signals, like the other session signals, are written only when the return FIFO is empty. Under a long FIFO backlog, credits return late. That throttles a gateway client (it is paused longer) but cannot deadlock it: claims and FIFO drain do not depend on gateway intake.
- **Budget is per session, summed across workers** — conservative: one session's routed acks on any single worker are ≤ the budget.
  - N stalled gateway sessions can still hold N × budget acks on one worker. The worker's `ackRoom_` throttle remains the backstop: more than 16 fully stalled sessions at the default could still cause ack-room op pauses.
- **Remaining legacy-transport tests:** the two D8b real-driver tests (`KilledPausedClientsSessionAndAcksAreFreedRegression`, `PausedInvokerClientSurvivesNotConnectedRegression`) still run on the legacy transport and wait for "worker holds > 256 acks or paused". They pass. Moving them to the derived transport is a small, separate follow-up; their comments still say the pause "can lag (D8c)".
- **Changed counter meaning:** `heldProduceAbortsForTest()` now counts every paused-produce ABORT, Held or no credit.

## MAJOR-1: per-worker routed cap

**The worker's ack queue is now split into two fixed shares.** `SessionAckSink::kAckCapacity` goes from 16384 to **32768** (40 B per entry, 1.25 MiB, on the heap).

| Share | Size | What it covers |
|---|---|---|
| `Worker::kAckReserve` | 16384 | The worker's own intake: owed returns at their ceiling (8192), one full op drain (4096) and one full direct-ingress poll (4096). |
| `Worker::kRoutedAckBudget` | 16384 | Gateway-routed produces only. A `static_assert` ties `ClientGateway::kWorkerRoutedCap` to this value. |

- The old header claim that "16 sessions fit" was wrong: 16 × 1024 *was* the whole queue, with no reserve left. That text is replaced by the derivation above.

**The gateway counts forwarded, unclaimed produces per worker.**
- It keeps `routedInFlight_[w]` for each worker, plus a count per session and per worker in `Session::produceInFlightOn`.
- A Credit signal names its worker (`ret.partition`), so the gateway subtracts it from the right worker.
- `closeSession_` gives the session's whole share back on every worker at once.
- No number of stalled gateway sessions can reach the reserve. Therefore, unless a *direct* client holds acks, `ackRoom_()` always leaves room for one op drain plus one poll.

**What happens when a worker is full.**
- The gateway checks the owning worker's cap at the start of `handleProduce`, right after the partition and intended-role checks.
- At that point nothing has been validated or answered yet; only liveness has been touched. So a refused frame is simply not consumed.
- `handleProduce` and `onClientFrame_` now return `false` in that case. The controlled poll ABORTs the frame, and Aeron redelivers it on the next poll.
- The worker index comes from the same router arithmetic `enqueueOp` already uses.

**Fairness rule.**
- In the cap's last quarter (the "congested band", 12288..16384) the gateway admits only **light** sessions: those with fewer than 64 produces in flight to that worker.
- A stalled session sits at its whole budget (1024 by default, up to 4096), so it is always paused first.
- The band's 4096 slots let up to 64 light sessions (a new client, an interactive producer) keep being served.
- The hard cap is never exceeded. A `static_assert` guarantees the band always has room for at least 64 light sessions.

## MEDIUM-1: one helper sets the credit flag

- `Worker::produceAnswer_(ProduceOrigin, sid, corr, topic, partition)` is now the **only** place that sets `gatewayCredit`.
- Both answer constructors use it: `produceCore_`'s result shell and `refuseNotOwned_`. The origin argument has no default, so a new answer site must choose one.
- Every other answer path copies `produceCore_`'s shell: refusals, parked waiters, HW fire, timeout, §3.2 failure, fsync completion and purge.

- **LOW-5:**
