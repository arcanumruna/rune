# D8d review: direct-path (worker-ingress) ack budget

- **Reviewed:** `rune-broker-wt42`, branch `fix/d8d-direct-path`, commit `bb1df9b` (base `b1aa4de`).
- **How:** read-only. I read the full diff, then traced every answer path in `Worker.h` and `SessionAckSink.h` and the gateway's signal handling. I re-ran the existing `build-fast` binaries filtered to `*Direct*`: sink 4/4, worker ack 4/4, gateway notify 1/1, all green. I did not build mutants.

## Verdict

**APPROVE WITH CHANGES.** There are no CRITICAL or MAJOR findings.

- Budget conservation is exact on every path I traced.
- The three-way split of the ack queue fits exactly, and the static_assert enforces it.
- The Expire signal path is never lossy.

Two MEDIUM findings should be fixed or explicitly accepted before merge:
- the congested band can be entered for good with no expiry by very few stalled direct sessions;
- after an expiry, the victim's backlog is appended without being acked, which widens the duplicate window beyond D8c's.

Counts: CRITICAL 0 · MAJOR 0 · MEDIUM 2 · LOW 4.

## Check (1): budget conservation, verified clean

Admission and return pair up exactly once on every path:

- **Admission.** It is counted only on a CONTINUE (`Worker.h:5047`). A refused frame is ABORTed, and its re-delivery is re-admitted from scratch, so it is never counted twice.
- **Every answer comes from one shell.** Each answer of a direct produce copies `produceCore_`'s shell, which carries `ret.directAck`. That covers:
  - the inline refusals (NotLeader, role gate, rcGate, Internal, empty batch, MessageTooLarge, schema, PSM gate, handleProduceBatch errors);
  - the acks=leader and acks=0 OK. acks=0 is still answered on the direct path (`acksAll = acks != 0`), so it never leaks;
  - the acks=all waiter: HW fire, timeout and the §3.2 NotLeader;
  - the ownership-move sweep and `failOwnPending_` (NotLeader / StorageError);
  - the Strict path: fsync completion, the seal-gated fire, Strict acks=all moving to `pendingAcksAll_` (`ret` moved), and submit-ring-full Internal.
- **Every answer reaches the sink once.** Each one goes `enqueueReturn_` → `emitProduceAck_` → the sink, exactly once. The runtime notification copy (`deferAck`) carries `directAck`, but it is not encoded and never reaches the sink.
- **Undecodable frames.** They are given back once (`Worker.h:5105`) and produce no answer. Frames shorter than 16 B are never admitted.
- **Every way out of the sink returns the unit once:**
  - claimed: OK or refusal (`else if (a.direct)` after the credit branch, so never both);
  - fatal claim, then the following acks of that session in the PubFailed branch (`:309`);
  - an unknown or closed session, via the orphan drop.
- **Session close.** `erase_` zeroes the session's share at once. The worker total returns when the queued acks drop. A closed session's *owed* acks hold the total until they fire or time out, which is bounded by `ackTimeoutNs_`.
- **Re-announce.** It keeps the slot, so the per-session count survives a publication restart.
- **TotalOnly.** It is counted in the total only and returned in the total only, so the per-session count can never go below what was counted. The `e.direct != 0` guard is never needed on the paths I traced.
- **Duplicates and retransmits.** Aeron delivers each frame to the image once. An idempotent duplicate is answered once, on its original's condition.
- **Layout.** The `Edges` size is unchanged (24 B), and `AckEntry` stays 48 B (`direct` sits in the padding after `credit`).

No leak and no double decrement found.

## Check (2): arithmetic, verified clean

| Term | Size |
|---|---|
| kAckReserve = 8192 + 4096 + 4096 | 16384 |
| kRoutedAckBudget | 16384 |
| kDirectAckBudget = 16384 − 1024 − 4096 | 11264 |
| Routed + direct + held-PushRead cap + one op drain = 16384 + 11264 + 1024 + 4096 | 32768 = kAckCapacity, exact |

- **What A + O can hold.** The ack queue plus owed returns can only contain:
  - direct answers (counted from admission, queued or owed);
  - routed answers (inside the routed budget, LOW-R1 window aside);
  - held PushReads (static cap 1024; `heldPushReads_.size() < kMaxHeldPushReads` at `Worker.h:2646`).
- **Nothing else enters.** Ownership purges only turn owed answers into queued ones, with no net change.
- **Op drains keep room.** `ackRoom_() ≥ 4096` holds whatever direct clients do, so op drains (`Worker.h:~2000`, gated on `ackRoom_`) are never starved by direct sessions.
- **The direct poll is still bounded.** `ingressPollBudget_` still caps K at `ackRoom_`, so admission can never overflow the queue.

## Findings

### MEDIUM-1: few stalled direct sessions park the worker in the band for good, with no expiry

- **Where:** `SessionAckSink.h:461-467` (band admission), `:664-670` (an episode starts only on a FULL share), `:444` (band = the last quarter).
- **Scenario** (production defaults, `gatewayFragmentLimit = 4096`, the configuration the reserve is sized for and the tests use):
  1. Stalled direct session S1 is held at its per-session budget of 4096. S2 is held at 4096, so the total is 8192.
  2. S3 is admitted up to 8448 (256 acks) and is then refused in the band (`mine ≥ 64`).
  3. The share is now in the band but **not full**, so `directFullThisPass_` is never set: no episode, no deferred passes, no expiry.
  4. To reach full (11264), 2816 more acks are needed from *light* sessions, each stopping at 64. That is 44 more stalled sessions.
- **Effect.** For 3 to about 46 stalled direct sessions, the worker stays in the band until the D8b held reaper closes them (lease of about 10 min).
  - During that time, every healthy direct session with 64 or more answers outstanding is throttled to 64 in flight. Pipelined acks=all producers count here, since their parked waiters count from admission.
  - At the default fragment limit of 256, about 33 stalled sessions reach the band.
- **How this compares with D8c.** D8c's gateway band has the same shape, but there it takes 12 stalled sessions (per-session budget 1024). D8d's 4096 budget lowers the threshold to **3**.
- **Overstated claim.** The report says "stalled sessions run out first" and frames expiry as the remedy. It does not cover the band-not-full steady state, which is where 3 stalled clients actually leave the worker.
- **Fix options:**
  - also count a deferred pass when a *band* refusal hits a held session at 64 or more (start the episode at the band, not only at the hard cap);
  - or lower the per-session direct budget so that `band / budget` matches D8c (about 12).
- **Regression test** (the formula from the D8c review): `band / budget + 1` stalled sessions, then assert that a healthy session with more than 64 in flight is not capped (or that an expiry fires).

### MEDIUM-2: after an expiry, the victim's ABORTed backlog is appended and never acked

- **Where:** `SessionAckSink.h:470` together with `Worker.h:5047`. The worker never refuses a produce from an unknown session (I1 forbids that).
- **Scenario:**
  1. The victim is held, so its image is full of offered but ABORTed frames: up to its term window, which can be MBs.
  2. The Expire signal arrives, the gateway closes the session, and the worker's `erase_` runs.
  3. On the next poll, `admitDirect` finds no session: kTotalOnly, no held check, counts as light. Every backlog frame is admitted and **appended**.
  4. Their answers drop as orphans at the next flush.
  5. The client got SessionExpired and resends every produce it never saw acked. Every backlog frame is duplicated for a non-idempotent producer.
- **How D8c differs.** On D8c's gateway path, frames of a closed session are dropped before the append (`ClientGateway.cpp:1749`, UnknownSession), so only what was already in flight duplicates.
- **Overstated claim.** The report says "the same trade-off as D8c". That is wrong: the direct path's duplicate window is the victim's whole buffered backlog.
- **Scope.** This exists for every direct-path close (reap, Failed). D8d adds a trigger that targets exactly the sessions with the largest backlog.
- **Fix options:**
  - remember recently expired or closed session ids on the worker (a small fixed ring, tombstoned until the lifecycle position passes) and ABORT or drop their frames without appending;
  - or at least correct the report and document the duplicate scope.

### LOW-1: the victim is not re-checked when the Expire is reported

- **Where:** `SessionAckSink.h:483-488`.
- **Problem.** The victim is chosen in pass N but reported in a later pass (it is retried while the return ring is full), and the close comes back over the lifecycle ring. If the session resumes reading in between (it claims acks, `directTag` is set, it is no longer held), it is still expired.
- **D8c difference.** D8c's gateway expiry is synchronous and has no such window.
- **Cost.** One avoidable reconnect plus duplicates.
- **Fix.** In `reportDirectExpiry`, if the victim is no longer held or was marked as a reader, cancel: clear `expiring`, decrement `expiringCount_`, and do not report.

### LOW-2: "held" includes sessions whose publications are still connecting

- **Where:** `SessionAckSink.h:680`. `heldPass_` is set for the PubAnnounced, PubResolving and NOT_CONNECTED states.
- **Problem.** A brand-new healthy client can be the "largest held share" during a full episode. Its first burst is admitted before its ack publication connects, and it has had no claims yet, so no reader mark. It can then be expired instead of a truly stalled session.
- **Fix.** Only consider PubReady sessions that are back-pressured (`blockedPass` with the claim result BACK_PRESSURED), or a session whose `lost` is set (a dead client).

### LOW-3: two answer paths have no worker-level test

- **Undecodable frames.** `Worker.h:5105` (`releaseDirect` on an undecodable frame) is covered only by the sink unit test of the method. A mutant deleting the Worker call site survives every listed test. That mutant leaks one unit of the share per malformed frame, and a client can send those at will.
- **Parked purges.** The parked-purge returns (the ownership-move NotLeader sweep, `failOwnPending_`, Strict submit-ring-full) are not exercised with direct tags. They are correct by the shared-shell construction, but nothing pins that.
- **Fix.** Add a real-driver worker test that offers N malformed frames on the direct image and asserts `directAcksInFlightForTest() == 0`. Add a parked acks=all, then ownership-move case to `DirectBudgetReturnsToZero…`.

### LOW-4: an Expire on a pending connect logs the wrong reason

- **Where:** `ClientGateway.cpp:1235`.
- **Problem.** An Expire for a pending-connect session falls into the Failed branch's pending-drop log line: "its ack publication … can never deliver". It is not counted in `directShareExpiries_`.
- **Impact.** Diagnostics only.

## Check (3): expiry, other points verified

- **One victim, consistently.** "Held + largest + not a reader in this episode + one per episode" is implemented consistently. The `expiring` mark moves with its key in the backward-shift `erase_`, and `expireUnreported_` is cleared before `keys_[i] = 0`.
- **The Expire signal is never lost.** If `trySessionSignal_` fails (return FIFO not empty or ring full), it is retried the next pass. A victim that closes first is cleared and never reported. At the gateway, a duplicate Expire is a no-op, since `closeSession_` returns false and there is no pending entry.
- **"Close never arrives".** `closeSession_` always calls `sessionAnnouncer_.close`, which retries until every worker has it, and the pending-connect path closes when `announceBegun`. I found no path where a reported Expire leaves `expiringCount_` stuck. If one appeared, the cost would be liveness only (no further expiries); the caps still hold.

## Check (4): hot path, acceptable

`admitDirect` costs, per direct frame:
- one open-addressing probe (`keys_`, 32 KiB);
- one `edges_` read and one increment;
- a few predictable branches.

There is no allocation, no virtual call, no atomic and no `std::function`. A claimed direct ack adds one inlined `directDone_`.

- **Probe cost.** Before D8d, the probe was skipped when nothing was held. Now it always runs: roughly 1 to 2 cache lines per frame. That is negligible at the bench's frame rates. For high frame-rate, small-batch workloads it is the only new cost.
- **Cold path.** `directEpisode_` is marked cold but runs every pass while an episode is open. That is cheap: the 4096-slot scan runs once per 64 deferred passes.
- **Bench.** The report's 7-vs-7 saturation means overlap (172k vs 174k). It is a sanity check, not a microbenchmark, which the report says itself.
